# Bisale

**Bisale** is a simple, beginner-friendly programming language and interpreter written in Python.

Bisale is currently in an early development stage. The current implementation is being built manually to explore how a programming language's **lexer** and **parser** work.

## Current Syntax

### Integer Variables

Use `int()` to declare integer variables:

```bisale
int(a)
```

A variable without an assigned value starts with `0`.

You can declare multiple variables:

```bisale
int(a,b,c)
```

You can also assign values during declaration:

```bisale
int(a=1)
int(b=2)
```

Assignments and default values can be mixed:

```bisale
int(a=1,b,c=3)
```

This creates:

```text
a = 1
b = 0
c = 3
```

## Example

A current Bisale program:

```bisale
int(i=1,j=1)
int(k)
int(l=2,w)
```

The current parser produces:

```text
{'i': 1, 'j': 1, 'k': 0, 'l': 2, 'w': 0}
```

## Source Files

Bisale source files use the `.bisale` extension.

For example:

```text
example.bisale
```

The Python interpreter asks for the Bisale filename:

```text
Enter Bisale name to cook:example
```

It then reads `example.bisale`.

## Interpreter Architecture

The current implementation follows this basic pipeline:

```text
.bisale source
      ↓
    Lexer
      ↓
    Tokens
      ↓
    Parser
      ↓
 Variable dictionary
```

### Lexer

The lexer reads the Bisale source code character by character and converts it into tokens.

For example:

```bisale
int(a=1)
```

is converted into tokens similar to:

```text
INT
LEFT_PARENT
IDENTIFIER
EQUAL
INTEGER
RIGHT_PARENT
```

The lexer currently recognizes:

| Token          | Meaning                  |
| -------------- | ------------------------ |
| `INT`          | `int` declaration        |
| `OUTPUT`       | `thojpav` output keyword |
| `LEFT_PARENT`  | `(`                      |
| `RIGHT_PARENT` | `)`                      |
| `EQUAL`        | `=`                      |
| `COMMA`        | `,`                      |
| `SEMICOLON`    | `;`                      |
| `IDENTIFIER`   | Variable name            |
| `INTEGER`      | Integer value            |

### Parser

The parser reads the tokens generated by the lexer and builds a Python dictionary containing the declared variables and their values.

For example:

```bisale
int(a=10,b,c=5)
```

produces:

```python
{
    "a": 10,
    "b": 0,
    "c": 5
}
```

## Current Features

* [x] `.bisale` source files
* [x] Character-by-character lexical analysis
* [x] Token generation
* [x] Integer variable declaration
* [x] Multiple variable declarations
* [x] Integer value assignment during declaration
* [x] Default value `0`
* [x] Mixed assigned and unassigned variables
* [x] Recognition of `thojpav` by the lexer
* [ ] Variable output/execution with `thojpav()`

## Future Output Features

The current `thojpav()` implementation is intended to be the beginning of Bisale's output functionality.

Future versions may introduce additional output-related syntax and capabilities. These may include:

* Outputting multiple variables.
* Outputting integer values directly.
* Outputting text or other supported data types as the language expands.
* More flexible output statements.
* Additional output-related syntax as the language develops.

These are **future possibilities**, not currently implemented features.

## Limitations

The current implementation is a basic lexer and parser and has several limitations:

* Only integer variables are currently supported.
* Negative integers such as `-1` are not currently recognized as `INTEGER` tokens.
* Decimal numbers are not supported.
* Input statements are not supported.
* Arithmetic operations such as `+`, `-`, `*`, and `/` are not yet supported.
* `thojpav()` is recognized by the lexer, but output execution is not yet implemented by the parser.
* Invalid or incomplete syntax can cause Python `IndexError` exceptions because the parser currently assumes some token positions exist.
* Invalid integer assignments can result in parsing problems.
* Unsupported statements may be ignored by the current lexer/parser instead of producing Bisale-specific errors.
* Variable redeclaration currently overwrites the previous value in the Python dictionary.
* Whitespace is currently ignored by the lexer, so some malformed input can be combined into an unexpected identifier.
* The entire `.bisale` source file is currently read into memory before lexical analysis.
